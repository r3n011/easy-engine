# 调度器与运行语义规范

> 积木语言最难的不是积木，是**什么时候停、什么时候继续**。
> 这份文档把 M2 定下来的语义写死，避免以后"这里为什么会这样"的反复。
>
> 实现：`runtime/ee/runtime.gd`（调度器）、`runtime/ee/thread.gd`（线程）
> 验证：`runtime/tests/m2_tests.gd`（84 项，全绿）

## 一、为什么不用协程（await）

最省事的做法是让每个脚本变成 GDScript 协程，`yield` 一下就暂停。**但这条路走不通**：

- 「停止这个脚本」「停止该角色的其他脚本」要求**从外部**打断一个正在等待的脚本
- 「广播并等待」要求**从外部**检查一组脚本是否跑完
- 克隆体被删除时，它的所有脚本必须立刻停

协程做不到这些。所以采用和 scratch-vm 一样的做法：**显式的帧栈**。
线程自己就是一个数据结构，随时可以暂停、检查、杀掉。

```gdscript
帧 = { ops: Array, idx: int, loop: "", left: 0, cond: null, warp: false }
```

| loop | 含义 |
|---|---|
| `""` | 顺序块 |
| `"repeat"` | 执行 `left` 次 |
| `"forever"` | 永远重复 |
| `"while"` | 每轮前重算 `cond` |
| `"warp"` | 原子区（内部不让步） |

## 二、一帧里发生什么

```
step(delta):
  1. now += delta；frame += 1
  2. 让"等待条件已满足"的线程恢复
  3. 逐个执行可运行的线程，直到它让步或结束
  4. 回收结束的线程
```

**第 3 步遍历的是本帧开始时的线程快照**，所以：

> **本帧内新启动的线程（广播触发的、克隆体启动的）留到下一帧才跑。**

这条让"一帧内发生什么"完全可预测，帧计数才能稳定断言。
（与 scratch-vm 的 `forEach` 行为一致。）

## 三、★ 循环每轮让步

```
重复执行 3 次 { 将 计数 增加 1 }
```

**这会花 3 帧**，不是 1 帧。每轮结束让出一次执行权。

为什么：Scratcher 的直觉就是这样的——`重复执行` 里放 `移动` 会看到角色一帧走一步。
如果改成"循环一口气跑完"，所有人的动画和手感都会变，这是不可接受的行为差异。

不想让出就用 **warp**（「不刷新屏幕执行」）。详见下一节。

| 结构 | 是否每轮让步 |
|---|---|
| `control.repeat` | ✅ |
| `control.forever` | ✅ |
| `control.while` / `重复执行直到` | ✅ |
| `control.if` / `if_else` | ❌（只是分支，不消耗帧） |
| 顺序块 | ❌ |

## 四、warp：原子执行

```
不刷新屏幕执行 { 重复执行 100 次 { ... } }
```

`enter_warp()` → `warp_depth += 1` → 循环不再让步 → `exit_warp()`。

**两道保护**（缺一个都会让用户"程序卡死"）：

| 保护 | 阈值 | 行为 |
|---|---|---|
| warp 超时 | 0.5 秒 | 强制让步一帧，并重置计时（对应 Scratch 的 warp timer） |
| 单帧 op 预算 | 2,000,000 | 强制让步并发告警（防止非 warp 的死循环卡死） |

这两条是**保护而不是正常路径**：触发就说明用户写了死循环，告警会告诉他。

## 五、等待与恢复时机

| op | 何时恢复 |
|---|---|
| `control.wait` | `now >= 执行时刻 + 秒数`。**等待 0 秒也让出一帧**（这是"主动让出执行权"的惯用写法） |
| `control.wait_until` | 每帧重算条件，成立即恢复 |
| `event.broadcast_wait` | 所有被启动的线程都结束 |
| `sound.play`（等待完成） | 无渲染环境下一帧即视为播完（M3 接真实时长） |

注意 `wait 0.5` 的到期时刻是**执行到这条积木的时刻 + 0.5**，不是"这一帧开始时 + 0.5"。
所以从第 1 帧（now=0.1）开始等待，会在 now=0.6 恢复，而不是 0.5。

## 六、广播

```
广播 [消息]            → 启动所有匹配的接收脚本，自己立刻继续
广播 [消息] 并等待      → 启动后挂起，直到它们全部结束才继续
```

- `广播` 不等待：接收方在**下一帧**开始跑（因为帧内新线程下一帧才跑）
- `广播并等待` 收到的是**本次启动的那一批线程**，之后新启动的不算

匹配规则：帽子的 `kind == "broadcast"` 且 `params.message` 与广播的消息相等。

## 七、克隆体

```
克隆 [目标]           → 从目标复制一份，触发它的「当作为克隆体启动时」
删除此克隆体          → 停掉它的全部线程并销毁
```

| 规则 | 说明 |
|---|---|
| 局部变量/列表 | **副本**。克隆体改自己的不会影响原型 |
| 全局变量 | 共享 |
| 实体状态（位置/大小/特效） | 复制原型的当前值 |
| 数量上限 | 默认 300，超出时**记告警并忽略**（不报错，不崩） |
| 原型被删除 | 克隆体仍存活（它们有自己的状态） |
| 克隆体 id | `原型id#序号`，便于调试 |

## 八、变量作用域

| scope | 行为 |
|---|---|
| `"auto"`（默认） | **先找局部，再找全局**。所以克隆体的局部变量能遮蔽全局同名变量 |
| `"global"` | 强制读写全局 |
| `"local"` | 强制读写本目标的局部 |

`"auto"` 是默认也是唯一"聪明"的行为：用户不用知道作用域这回事。
但**写**的时候有个约定：如果局部没有同名变量，`auto` 写的是全局——
否则「设 分数 为 0」会莫名其妙地在每个角色上各创建一个局部变量。

## 九、停止语义

| 积木 | 行为 |
|---|---|
| 停止 当前脚本 | 立刻结束本线程（含被自定义积木调用的传播） |
| 停止 该角色的其他脚本 | 杀掉同目标的其他线程，自己继续 |
| 停止 全部脚本 | 杀掉所有线程并清空线程表 |

**绿旗不会自动停止现有脚本**——由调用方决定（编辑器在点绿旗时先 `stop_all()` 再 `green_flag()`）。

## 十、值语义（要点）

完整规则在 `runtime/ee/values.gd` 的头部注释里。三条最要紧的：

1. **比较**：两边"都能当数字"就走数字比较，否则字符串比较。
   因此 `"10" > "9"` 为**真**（数字），比 JavaScript 的字典序直觉更好预测。
2. **加法**：两边都能当数字就相加，否则拼接。所以 `"abc" + 4` = `"abc4"`。
3. **转布尔**：非空字符串一律为真，**包括字符串 `"false"`**。
   这样就不会有「字符串 `"false"` 到底算真还是假」的歧义。

失败值不隐藏：除以零得 `Infinity`，`0/0` 得 `NaN`，显示层负责把它们说成人话。

## 十一、表达式（逃生舱①）

受限语言，不是 GDScript。语法：`or → and → not → 比较 → ± → ×÷% → 负号 → ^ → 基本项`。

- 变量名直接写（走 `auto` 作用域查找）
- 白名单函数：`min max abs floor ceil round sqrt pow sign sin cos tan atan2 log exp clamp lerp deg2rad rad2deg random randi len str num bool`
- **编译一次、求值多次**：循环里的表达式不会重复解析（`runtime.eval_expression` 带缓存）
- 出错时线程以明确的错误信息失败，不会静默返回 0

## 十二、扩展如何介入

这一层刻意做成"扩展也能做"的：

| 能力 | 扩展怎么做 |
|---|---|
| 加自己的 op | 写 `ops.<扩展id>.json` 声明 + `providers/<扩展>.gd` 实现 |
| 加自己的控制流 | 在 provider 里用 `ctx.push_loop("myloop", ops, n, cond)` |
| 加自己的挂起语义 | 声明 `yields: true`，实现里用 `ctx.yield_tick()/yield_time()/yield_until()/yield_threads()` |
| 加自己的值类型 | op 声明 `pure: true`，返回值直接参与求值 |

**调度器里没有任何针对具体 op 的特例**：它只做"取下一个 op → 交给 provider"。
这就是为什么这套设计能扛住后期扩展。

启动时还会做一次校验：**每个声明的 op 必须有对应实现**，缺了在启动就报错，
而不是跑到那一行才崩。

## 十三、契约清单（M3 接 Godot 时必须保持）

- [ ] `yields` 语义不变（循环每轮让步、warp 原子、保护阈值）
- [ ] 帧内新线程下一帧才跑
- [ ] 克隆体局部变量是副本
- [ ] 变量 `auto` 作用域规则
- [ ] `Target` / `NodeBridge` 的接口形状（M3 只换桥的实现）
- [ ] 值语义规则（`values.gd` 是唯一来源）
