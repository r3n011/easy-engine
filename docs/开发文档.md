# Easy Engine 开发文档

> 面向：接手这个项目的人（包括三个月后的我自己）。
> 目标：看完这一篇，你能独立加积木、改运行时、修桥、打包发布。

---

## 1. 这是什么

**一个把 Godot 改造成"积木编程"的引擎。**

- 用户打开的是**我们编译的 Godot 编辑器**，底部多一个「积木」面板
- 拖积木 → 存进场景（`.tscn`）→ 点运行 → 导出成独立 exe
- 面向**自学**的孩子：全中文、每个选项悬停有人话解释

和 Scratch 的关系：
| | Scratch | Easy Engine |
|---|---|---|
| 积木界面 | 自己的渲染器 | **直接用 Scratch 的渲染内核**（scratch-blocks），所以长一样 |
| 能做什么 | 2D 舞台 | 2D + **3D** + **真物理** + 粒子 |
| 发布 | 只能在浏览器 | **导出 exe**，发给谁都能双击玩 |

一句话：**用孩子已经会的积木，做 Scratch 做不到的东西。**

## 2. 架构一句话

```
Godot 编辑器（我们编译的）
├── 引擎模块 modules/easyblocks/     ← C++：积木是 Resource，运行器是 Node
└── 底部面板「积木」
    └── WebView2 子窗口               ← 网页：scratch-blocks 负责画和拖
        └── bridge.js  ⇄  C++ (postMessage / ExecuteScript)
```

**为什么界面是网页**：Godot 没有内嵌网页的节点，我们用 WebView2 起一个原生子窗口叠在编辑器上。
**为什么积木数据不在网页里**：数据存在 `BlockProgram`（Resource）里，跟着 `.tscn` 走。网页只是"编辑时的视图"。

## 4. 数据流：从拖积木到跑起来

```
① 用户拖积木
     网页里是 scratch-blocks 的 Blockly 结构
     250ms 防抖后 bridge.js 的 workspaceToProgram() 转成我们的 JSON
② 推给引擎
     window.chrome.webview.postMessage({type:'program', program:[...]})
③ C++ 收下
     BlockRunner::set_program() → BlockProgram::set_scripts() → compile()
     编译产物是 IR（Array<Dictionary>），顺手记一步撤销
④ 保存
     BlockProgram 是 Resource，存进 .tscn（Ctrl+S 就行）
⑤ 运行
     BlockRunner::_ready() → start() → 按帽子建线程 → 每帧 _step()
```

反向（选中节点时）：
```
选中节点 → 找它的 BlockRunner → 读 BlockProgram.scripts
        → JSON::stringify → web_view->eval("eeLoadProgram(...)")
        → 网页重建积木（programToXml）+ 回显一次做往返校验
```

**往返校验**很重要：网页如果对某个积木"画不出来"，回显就会少东西，
引擎侧立刻能发现，不会静默丢积木。

## 5. 程序格式与 IR

### 5.1 积木树（存在 BlockProgram.scripts）

```json
[
  {
    "top": {
      "block": "core.event.when_flag_clicked",
      "inputs": {
        "BODY": { "stack": {
          "block": "core.control.repeat",
          "inputs": {
            "TIMES": { "value": 10 },
            "BODY": { "stack": { "block": "core.motion.change_x",
                                 "inputs": { "DX": { "value": 5 } } } }
          }
        } }
      }
    }
  }
]
```

规则：
- `block`：我们自己的积木 id（不是 Scratch 的）
- `inputs.NAME` 两种形态：
  - `{ "value": 字面量 或 子积木 }`
  - `{ "stack": 积木串 }`（第一块后面用 `next` 串）
- 自制积木额外字段：`proccode` / `params`（定义）、`name`（参数）

### 5.2 IR（编译产物，只在内存）

```json
{"op":"event.hat","kind":"flag","body":[
  {"op":"control.repeat","times":10.0,"body":[
    {"op":"motion.change_x","dx":5.0,"target":"@self"}]}],"params":{}}
```

- `target`：`@self` 或节点路径或纯名字（`_resolve_target` 三种都认）
- 每个 op 的参数名来自 `ops.*.json` 的 `args` + `defaults`

**为什么分两层**：编辑时随便改、能报错；运行时只认 IR，快且不用碰积木结构。
以后做"代码转积木"也只需要产出 IR。

## 6. 运行时语义

实现在 `block_runner.cpp`，语义照 `docs/format/EE-SCHEDULER.md`（M2 定稿）：

- **显式帧栈**，每帧一个 `Frame { ops, idx, loop, left, cond }`
- **循环每轮让步**：`repeat`/`forever`/`while` 每跑完一轮 `status = YIELD_TICK`
- **warp 内不让步**（`LOOP_WARP`），但超过 0.5 秒强制让步
- **单帧 op 预算** 2,000,000，防止不让步的死循环卡死
- **等待**：`YIELD_TIME`（`resume_at`）/ `YIELD_UNTIL`（每帧求值条件）/ 等音频播完
- **自制积木**：每次调用压一层 `Dictionary` 作用域，帧类型 `LOOP_PROC` 关闭时弹栈
- **克隆体**：`duplicate()` 子树 + `ee_clone` 标记；克隆体只启动 `clone_start` 帽子
- **物理碰到**：接 `body_entered` 信号，命中后新建线程

### 值语义（`values.cpp`）

| 操作 | 规则 |
|---|---|
| 转数字 | 布尔→0/1，字符串 trim 后能解析就用，否则 0 |
| 转字符串 | 整数值不带 `.0`；非有限值用 `Infinity` / `NaN` |
| 转布尔 | 空串/0/null 为假；**"false" 这种非空字符串为真** |
| 比较 | 两边都能当数字就数字比，否则字符串比 |

## 7. 加一个新积木：完整清单

以「让角色跳跃」为例。

### ① 定义（`modules/easyblocks/defs/blocks.xxx.json`）

```json
{
  "id": "core.motion.jump",
  "version": 1,
  "category": "motion",
  "shape": "stack",
  "message": "跳 %HEIGHT% 高",
  "args": { "HEIGHT": { "type": "number", "default": 100 } },
  "ir": { "op": "motion.jump", "height": { "$arg": "HEIGHT" }, "target": "@self" }
}
```

- 新的分类/扩展就新建一个 `blocks.ee.*.json`，`gen_defs.py` 会自动收进去
- `ir` 里的 `target` 写 `"@self"` 表示"积木挂在谁身上就作用在谁身上"

### ② 运行时（`block_runner.cpp` 的 `_exec`）

```cpp
if (op_id == "motion.jump") {
    if (Node2D *n2 = Object::cast_to<Node2D>(target)) {
        n2->set_position(n2->get_position() + Vector2(0, -num("height")));
    }
    return Variant();
}
```

### ③ 让用户能在编辑器里看到它

**情况 A：Scratch 本来就有这个积木**（比如 `motion_movesteps`）
→ 在 `web/app/bridge.js` 的 `MAP` 里加一行：

```js
{ s: 'motion_movesteps', e: 'core.motion.move_steps', inputs: { STEPS: 'STEPS' } }
```

**情况 B：Scratch 没有**（3D/物理/粒子这种）
→ 在 `web/app/blocks3d.js` 里用 scratch-blocks 定义，并加到工具箱分类：

```js
Blockly.Blocks['ee_3d_burst'] = stackDef('喷一下粒子 颜色 %1 数量 %2', [...]);
// 工具箱：cat 字符串里加 <block type="ee_3d_burst"></block>
// 映射：window.ee3dMap 里加一条
```

### ④ 悬停解释（`defs/tips.zh.json`）

```json
"core.motion.jump": {
  "tip": "让角色往上跳一下（不会自己落回来）",
  "args": { "HEIGHT": "跳多高，数字越大越高" }
}
```

然后跑一次 `python tools/gen-tips.py`（打包时也会自动跑）。

### ⑤ 编译验证

```powershell
powershell -File tools\build-engine.ps1
```

在 `test/` 下建一个最小工程跑一遍，确认数值对得上。

```powershell

powershell -ExecutionPolicy Bypass -File tools\build-engine.ps1 -Jobs 8  # 内存富裕时
```

```powershell
$env:EASYBLOCKS_SHOW_PANEL="1"   # 自动切到「积木」面板
```

## 10. 坑与约定（血泪清单）

### 编译相关

1. **模块里的 `.cpp/.h` 必须存 UTF-8 带 BOM**。MSVC 按系统代码页读中文会把字符串结尾的引号吞掉，
   报"字符串太长"。
2. **`String("中文")` 是 Latin-1**，必须 `String::utf8("中文")`。
3. **多行编辑不要用 PowerShell 的 `-replace`**：`` `n `` 会变成字面量，把 include 写成一行。
   用编辑器工具改。
4. **`env.Append(LIBS=[...])` 的名字会被 SCons 加平台后缀**；`.lib` 全路径塞 `LINKFLAGS` 又找不到。
   WebView2 因此改成**动态加载 DLL**。
5. **`HashMap` 不可拷贝**，不能放进 `Vector`；用 `Vector<Dictionary>`。

### 运行时相关

6. **`@self` 解析出来的节点可能已经不在树里**（比如"变成物理物体"换过节点）。
   `_resolve_target` 里要检查 `is_inside_tree()`，否则后面所有积木作用在已释放对象上。
7. **改节点类型只能"原地替换"**：新建目标类型 → 搬子节点 → 保持父节点/位置/兄弟顺序 → 删旧节点 → 改回名字。
8. **克隆体的绿旗帽子不能重跑**：`duplicate` 后先 `set_auto_start(false)`，加进树后再 `start_clone_hats()`。
9. **`body_entered` 需要 `contact_monitor = true` + `max_contacts_reported > 0`**，否则永远不触发。

### 网页相关

10. **浮出层积木在另一个 workspace**，`isInFlyout` 可能是 false。
    读程序时必须三重过滤：`!isInFlyout && !isShadow && b.workspace === workspace`。
11. **变量/列表必须先 `createVariable` 声明**，否则 `field_variable` 抛类型错误。
12. **XML 里列表字段要带 `variabletype="list"`**。
13. **`getFieldValue()` 对变量字段返回内部 id**，要名字得用 `field.getText()`。
14. **分类的 id 在 class 里**（`scratchCategoryId-motion`），不在 `id` 属性。
15. **帽子积木下面那串在 Scratch 里是 `next`**，我们的格式里是 `BODY`（映射表的 `nextFrom`）。
16. **独立块（如 `motion_bounce`）没有上下连接口**，给它写 `<next>` 会让整个加载抛异常。

### 工程相关

17. **`engine/godot` 是可丢弃的构建目录**，永远只改 `modules/easyblocks`。
    `sync-module.ps1` 用 `/MIR`，会删掉你在引擎树里手写的文件。
18. **`robocopy /MIR` 同理会清掉 `bin/easyblocks_web`**，所以网页资源在打包最后一步才复制。

### 还没实现的核心积木（拖出来会被跳过并警告）

| 积木 | 为什么 |
|---|---|
| `外观：颜色/鱼眼/旋转…特效` | 需要材质参数映射，还没做 |
| `外观：移到最前/最后一层` | 2D 需要 `z_index`，3D 需要排序，简单但没排上 |
| `侦测：询问并等待 / 回答` | 需要输入框 UI |
| `声音：音量 / 音效` | 需要 `AudioStreamPlayer.volume_db` 的语义对齐 |
| `数据：列表显示/隐藏` | 数据是全的，舞台上的列表 UI 没做 |
| `元积木（get_property / call_method…）` | 逃生舱，优先级最低 |

这些都是"拖出来不会有反应"的，所以宁可先不放进调色板 —— 工具箱里已经删掉了 Extensions。
